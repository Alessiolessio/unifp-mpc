# UniFP-MPC

The first working component exports the pretrained UniFP-Spot student to ONNX and checks native CPU inference against executed Isaac actions. The next experiment is one driven Spot in MuJoCo. Box pushing comes first, followed by uprighting a fallen traffic cone.

## Run the M1 checks

Run these commands from this directory on Linux x86-64 with the local UniFP-Spot checkout available.

```bash
export PATH="$HOME/.pixi/bin:$PATH"
export PIXI_CACHE_DIR="$PWD/.pixi/cache"
pixi install --locked
pixi run --locked build
../unifp-spot/.venv/bin/python -B tools/export_policy.py
pixi run --locked env PYTHONPATH=build python tests/check_replay.py
```

The project-local package cache is writable in this workspace. Pixi 0.84.1 accepts the v6 lock with `--locked`; `--offline` also works with the populated cache here. The build task runs CMake in Release mode with Ninja. MuJoCo headers and library come from the same wheel, and ORT headers and library come from one CPU development package. The export command runs on CPU in the source policy's Python environment. Only the ONNX graph crosses into the new runtime. To reproduce the export environment on another machine, UniFP-Spot supplies its own Linux uv lock. An out-of-tree environment can be created with `UV_PROJECT_ENVIRONMENT="$PWD/.export-venv" uv sync --frozen --no-install-project --project ../unifp-spot`, then used with `.export-venv/bin/python -B tools/export_policy.py`. The tested export used the already installed source environment. [Runtime manifest](pixi.toml) · [Runtime lock](pixi.lock) · [Source environment](../unifp-spot/pyproject.toml)

The exporter imports the tracked `ActorCritic` implementation and strictly loads all weights before extracting the deterministic encoder and actor. It checks the graph and numerical parity before writing `artifacts/encoder_actor.onnx`. The replay probe also needs the local Isaac recordings under `outputs/validation/free_space_x_reset_verified` and `outputs/mpc/latency_cpu_constant_writes_seed0`, the Judo checkout, and Menagerie's `boston_dynamics_spot` assets. Use `--source`, `--judo` and `--menagerie-spot` on the probe for other locations. The recordings and local MPC probes are outside UniFP-Spot's tracked source at the inspected revision. The graph export also works independently of those recordings. [Exporter](tools/export_policy.py) · [Replay check](tests/check_replay.py) · [Native check](tests/native_probe.cpp)

## Policy and model contract

One 20 ms policy tick covers four 5 ms physics steps. History is float32, oldest first, with zero padding at reset. Insert the current observation once, after setting the candidate command and before inference. Actor input is the newest 79 entries followed by the 64-value encoded history. The decoder estimates diagnostic quantities including synthetic external disturbances. [Environment](../unifp-spot/unifp_spot/envs/unifp_env.py) · [Observation definitions](../unifp-spot/unifp_spot/envs/base/mdp/observations.py)

| Frame slice | Quantity and scale |
|---|---|
| 0–1 | Base roll and pitch in radians |
| 2–4 | Body angular velocity ×0.25 |
| 5–23 | Joint position minus the task's default angle |
| 24–42 | Joint velocity ×0.05 |
| 43–61 | Previous applied policy action |
| 62–63 | Sine and cosine of the episode gait clock, period 0.64 s |
| 64–78 | Body velocity request (vx,vy) ×2, yaw rate ×0.25, EE (radius, elevation, azimuth), three zero orientation entries, yaw-frame EE and base force requests ×0.01 |

The runner sanitizes and clips frames to ±100. The environment sanitizes and clips actions to ±100 and targets `q_default + 0.25 * action`. XY velocity ranges are ±0.6/0.4 m/s, yaw rate ±0.6 rad/s. The EE sphere is centered at base position plus the yaw-rotated offset (0.35, 0, 0.12) m. Radius is 0.15–0.55 m, elevation −40° to +50°, azimuth ±90°. EE/base virtual command ranges are ±40/30 N per component. Only the independently scheduled external disturbance stream physically applies a wrench. The EE tracking reward offsets its Cartesian target by (commanded + external force)/200. Plan world-space targets and convert and project against each candidate's current base at each tick. [Spot overrides](../unifp-spot/unifp_spot/envs/spot/spot_pos_force_cfg.py) · [Reward](../unifp-spot/unifp_spot/envs/base/mdp/rewards.py) · [Projection](../unifp-spot/tests/probe_position_mpc.py)

arm_el0 fl_kn fr_kn hl_kn hr_kn   arm_el1 arm_wr0 arm_wr1 arm_f1x

MuJoCo's Judo model groups four complete legs before the arm. Resolve qpos, dof and actuator transmission indices independently by name. IsaacLab 3's root quaternion is xyzw and MuJoCo's is wxyz. Use the body frame for angular velocity and the yaw-only frame for the spherical task. The trained stance has front/hind hip pitch 0.9/1.1 rad, knees −1.5 rad, hip roll ±0.1 rad and initial base height 0.5 m. The task overrides the asset defaults and the leg gains. [Runtime articulation record](../unifp-spot/outputs/validation/free_space_x_reset_verified/report.json) · [MJCF actuator order](../judo/judo/models/xml/spot_primitive/actuator.xml)

**Model choice.** Start from Judo's Spot kinematics. At 20 positive-mass links, the maximum USD-to-compiled-MJCF differences were 9.32e-7 kg in mass, 3.86e-9 m in a local CoM coordinate and 1.77e-8 kg m² in a link-frame inertia tensor component. These compare authored nominal USD properties, with principal-axis rotations applied. The composed USD has 19 mesh, four sphere and two cube collision shapes. Judo uses boxes, capsules and spheres, including jaw approximations and explicit self-contact exclusions. The ground friction settings differ (Isaac static/dynamic 1.0 with average combine, Judo plane sliding coefficient 0.7). PhysX uses TGS and articulation iterations 4/0; Judo configures Newton/implicitfast at 10 ms. Joint damping, friction and contact compliance require driven checks. ## Planner decision and acceptance gates

Keep the existing NumPy CEM adaptation, its linear interpolation and evaluated-best selection in Python. Use one native UniFP policy/actuator/physics step for both execution and prediction. A small batch interface can take an executed snapshot and command schedules and return costs, validity and selected diagnostics. A direct fork of Judo's Spot backend would replace its observation, action, actuator and snapshot contract. SUMO's pool and Judo's shared ORT session are implementation references once a serial continuation agrees. The probe creates sessions for independent test calls; a production evaluator should reuse sessions, worker data and tensors.

The inspected PhysX GPU pilot spent 1.102/1.525 s mean planning for reach/wall with eight parallel samples and a dependent elite-mean pass. The published host regions put physics at 432/744 ms and encoder+actor at 53/53 ms across the two passes. The later one-pass CPU PhysX predictor with GPU execution, C++ actuation and ONNX took 136/189 ms mean and 145/198 ms p95 for planning. All 40 updates missed 100 ms. These historical workloads differ in placement and number of forecasts. A native box speedup requires a new same-task measurement. [Archived timing analysis](../unifp-spot/docs/mpc_latency.md) · [CPU run data](../unifp-spot/outputs/mpc/latency_cpu_constant_writes_seed0/latency_comparison.json)

**Box objective and success.** First minimize squared terminal horizontal distance of the box center to the goal, scaled by the proposed 5 cm success radius. Reject falls and divergent trajectories. A near-face start and a candidate aiming through the rear face give the first test observable object motion within the horizon. If most candidates leave the box stationary, add mean distance from the finger to that face. Add running goal error or command smoothness only if trajectories show late shoves or chatter. Proposed demonstration: from at least 20 cm away, move the box within 5 cm and stay there for 0.5 s with Spot standing. Compare final error, time in tolerance and success against hold and scripted pushes on the same starts, including an offset goal and a lateral start. Report the number of trials and failures.

**Cone objective and success.** Start with a settled fallen cone. Minimize terminal `1 − dot(R e_z, target_axis)`. The upright axis target makes yaw irrelevant; the positive direction distinguishes upright from upside-down and is invariant to quaternion sign. SUMO accepts dot ≥0.9 at one instant. Proposed demonstration: finish within 10° of world +z for 0.5 s after releasing the cone, with Spot standing. Log angular speed and final translation to detect a fly-through or ejection. For a task that specifies a full pose, score translation and the quaternion geodesic angle `2 acos(clamp(abs(dot(q,q_goal)),0,1))` on unit quaternions and set separate success tolerances. Add a contact approach term only if the terminal objective is flat across sampled trajectories.

For the force comparison, run the same nominal target with zero EE force, the target with a force command, and zero force with a Cartesian target shifted by the command divided by 200 N/m in the yaw frame. Keep all three projected commands in their common reachable range and match velocity offsets too if base-force commands are enabled. Report executed success, object error, gripper/object pair force and impulse, falls and forecast error at the prefix and horizon. A benefit from the force input requires improvement against the matched-target control.
